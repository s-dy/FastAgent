# 长短期记忆系统设计

## 一、概述

系统采用**两层记忆架构**，结合 LangGraph 的短期状态管理和长期记忆存储，实现"越用越智能"的个性化推荐：

```
┌─────────────────────────────────────────────────────────────┐
│                     短期记忆 (Short-term)                    │
│  载体: LangGraph CoordinatorState (内存)                     │
│  生命周期: 单次请求                                           │
│  内容: 已分配景点列表、每日摘要、中间状态                       │
└─────────────────────────────────────────────────────────────┘
                          ↑ 写入/读取
┌─────────────────────────────────────────────────────────────┐
│                     长期记忆 (Long-term)                     │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  长期记忆 - 偏好画像（Preference Profile）            │   │
│  │  载体: Redis Hash                                     │   │
│  │  生命周期: 永久                                       │   │
│  │  存储: 结构化数据（JSON）                             │   │
│  │  内容: 偏好频次、去过的城市/景点、预算习惯、酒店偏好      │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.1 设计目标

- **越用越智能**：通过记录用户的历史行程和偏好，后续规划时提供个性化推荐
- **避免重复推荐**：记住用户去过的城市和景点，避免重复推荐
- **预算参考**：记录用户的历史花费，为预算规划提供参考
- **性能优先**：记忆加载和存储不影响规划性能

### 1.2 记忆分层原则

| 记忆类型 | 存储位置 | 生命周期 | 访问方式 | 典型用途 |
|---------|---------|---------|---------|---------|
| **短期记忆** | LangGraph State | 单次请求 | 直接访问 State 字段 | 已分配景点去重、每日摘要 |
| **长期记忆** | Redis Hash | 永久 | Key-Value 精确查询 | 过滤去过的景点、预算参考 |
