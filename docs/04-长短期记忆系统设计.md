# 长短期记忆系统设计文档

## 一、背景与目标

### 1.1 现状分析

当前系统存在以下记忆相关问题（详见 `docs/problems/11-Memory记忆存储内容过于简单.md` 和 `docs/problems/07-Agent记忆检索的性能优化.md`）：

1. **记忆存储内容过于简单**：只存储了用户请求参数（目的地、偏好），没有存储规划结果、用户反馈等有价值的信息
2. **记忆检索重复调用**：一次行程规划中向量检索被调用 15+ 次，所有 Agent 查询相同内容，浪费 1.5-3s
3. **降级方案失效**：`EnhancedAgent._get_memory_context()` 中的向量检索代码被注释掉，降级方案返回空字符串
4. **记忆内容缺乏语义**：存储的 JSON 字符串语义信息弱，向量检索效果差
5. **只使用了 episodic 类型**：没有利用 working、semantic、preference 等记忆类型

### 1.2 设计目标

- **短期记忆**：在单次行程规划请求内，高效传递上下文（景点、天气、已分配资源等），避免重复检索
- **长期记忆**：跨请求持久化用户偏好和历史行程，实现"越用越懂用户"
- **检索性能**：整个请求生命周期内，向量检索最多执行 1 次
- **存储质量**：存储自然语言摘要而非简单 JSON，提升向量检索的语义匹配效果

## 二、整体架构

### 2.1 记忆分层模型

```
│  │  存储: 向量索引 + 元数据                               │   │
│  │  内容: 每次行程的自然语言摘要                           │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 请求生命周期中的记忆流转

```
┌─────────────────────────────────────────────────────────────┐
│                       请求进入                               │
│                                                             │
│  ① 从 Redis 读取用户偏好画像（结构化，O(1) 查询）            │
│  ② 从向量库检索相关情景记忆（语义检索，Top-3，仅 1 次）       │
│  ③ 合并为 memory_context 字符串，写入 CoordinatorState        │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                   LangGraph 执行规划                         │
│                                                             │
│  阶段1: AttractionSearchWorker + WeatherSearchWorker         │
│    - 读取 memory_context，影响景点搜索关键词                   │

│                                                             │
│  阶段2: DailyPlanningWorker（并行 N 天）                      │
│    - memory_context 注入景点/酒店/餐饮的 Prompt               │

│  阶段3: Synthesizer                                         │
│    - 使用短期记忆中的 daily_summaries 生成主题                 │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                     规划完成后                                │
│                                                             │
│  ④ 增量更新用户偏好画像到 Redis                               │
│  ⑤ 存储本次行程的自然语言摘要到向量库                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 三、详细设计

### 3.1 短期记忆：CoordinatorState 扩展

短期记忆的载体是 LangGraph 的 `CoordinatorState`，不需要额外的存储组件。当前 State 已经承担了短期记忆的角色（`completed_tasks`、`raw_attractions`、`raw_weather` 等），只需新增一个字段来承载从长期记忆加载的上下文。

#### 3.1.1 State 新增字段

```python
class CoordinatorState(TypedDict):
    # ... 现有字段保持不变 ...

    # 新增：从长期记忆加载的上下文（阶段1 开始前一次性加载）
    memory_context: str           # 合并后的记忆上下文文本，注入到各 Worker 的 Prompt 中
    user_profile: Dict[str, Any]  # 用户偏好画像（结构化数据，用于程序化过滤）
```

#### 3.1.2 memory_context 的使用方式

`memory_context` 是一段自然语言文本，在阶段2的各个 Prompt 构建函数中被注入到 user prompt 末尾：

```python
# prompts.py 中的 build_daily_attraction_prompt 等函数新增 memory_context 参数
def build_daily_attraction_prompt(
    day_num, destination, raw_attractions, weather_text,
    preferences, budget_level,
    memory_context: str = "",  # 新增
) -> str:
    prompt = f"..."  # 现有逻辑
    if memory_context:
        prompt += f"\n\n## 用户历史偏好参考\n{memory_context}"
    return prompt
```

#### 3.1.3 user_profile 的使用方式

`user_profile` 是结构化数据，用于程序化过滤（不经过 LLM）：

```python
# attraction_search_worker 中使用 user_profile 过滤已去过的景点

raw_attractions = [a for a in raw_attractions if a["name"] not in visited]
```

### 3.2 长期记忆 - 用户偏好画像（Redis）

#### 3.2.1 数据结构

使用 Redis Hash 存储，Key 为 `user_profile:{user_id}`：

```python
{
    # 基础统计
    "trip_count": 5,                    # 累计行程次数
    "last_trip_date": "2026-02-15",     # 最近一次行程日期

    # 偏好频次（JSON 字符串）
    "preferred_categories": '{"历史文化": 8, "自然风光": 3, "美食": 5}',
    "preferred_budget": '{"经济": 1, "中等": 3, "高端": 1}',
    "hotel_preferences": '{"连锁快捷": 2, "星级酒店": 3}',

    # 历史记录（JSON 字符串）
    "visited_cities": '["北京", "上海", "杭州"]',
    "visited_attractions": '["故宫", "天安门", "西湖", "外滩"]',

    # 预算统计
    "avg_daily_budget": "850.0",        # 平均每日花费
}
```

#### 3.2.2 读取接口

```python
class UserProfileService:
    """用户偏好画像服务"""

    def __init__(self, redis_client):
        self.redis = redis_client

    def get_profile(self, user_id: str) -> Dict[str, Any]:
        """读取用户偏好画像，不存在则返回空画像"""
        key = f"user_profile:{user_id}"
        raw = self.redis.hgetall(key)
        if not raw:
            return self._empty_profile()

        return {
            "trip_count": int(raw.get("trip_count", 0)),
            "last_trip_date": raw.get("last_trip_date", ""),
            "preferred_categories": json.loads(raw.get("preferred_categories", "{}")),
            "preferred_budget": json.loads(raw.get("preferred_budget", "{}")),
            "hotel_preferences": json.loads(raw.get("hotel_preferences", "{}")),
            "visited_cities": json.loads(raw.get("visited_cities", "[]")),
            "visited_attractions": json.loads(raw.get("visited_attractions", "[]")),
            "avg_daily_budget": float(raw.get("avg_daily_budget", 0)),
        }
```

#### 3.2.3 更新接口

规划完成后（`node_save_memory` 节点），增量更新用户画像：

```python
def update_profile_after_trip(self, user_id: str, trip_result: TripPlanResponse, request: TripPlanRequest):
    """行程完成后增量更新用户画像"""
    profile = self.get_profile(user_id)

    # 更新行程次数
    profile["trip_count"] += 1
    profile["last_trip_date"] = datetime.now().strftime("%Y-%m-%d")

    # 更新偏好频次
    for pref in request.preferences:
        profile["preferred_categories"][pref] = profile["preferred_categories"].get(pref, 0) + 1
    profile["preferred_budget"][request.budget] = profile["preferred_budget"].get(request.budget, 0) + 1

    # 更新去过的城市和景点
    if request.destination not in profile["visited_cities"]:
        profile["visited_cities"].append(request.destination)
    for day in trip_result.days:
        for attraction in day.attractions:
            if attraction.name not in profile["visited_attractions"]:
                profile["visited_attractions"].append(attraction.name)

    # 更新平均预算（滑动平均）
    actual_daily = trip_result.total_budget.total / len(trip_result.days)
    old_avg = profile["avg_daily_budget"]
    old_count = profile["trip_count"] - 1
    profile["avg_daily_budget"] = (old_avg * old_count + actual_daily) / profile["trip_count"] if profile["trip_count"] > 0 else actual_daily

    self._save_profile(user_id, profile)
```

### 3.3 长期记忆 - 情景记忆（向量库）

#### 3.3.1 存储内容

每次行程规划完成后，生成一段**自然语言摘要**并存入向量库。自然语言格式的优势在于语义丰富，向量检索时匹配效果远优于 JSON 字符串。

```python
def build_trip_memory_text(request: TripPlanRequest, result: TripPlanResponse) -> str:
    """构建行程记忆的自然语言摘要"""
    duration = len(result.days)
    attraction_names = []
    hotel_names = []
    for day in result.days:
        attraction_names.extend([a.name for a in day.attractions])
        hotel_names.extend([h.name for h in day.hotels])

    # 去重
    unique_attractions = list(dict.fromkeys(attraction_names))
    unique_hotels = list(dict.fromkeys(hotel_names))

    memory_text = (
        f"{request.start_date}，用户去{request.destination}旅行{duration}天，"
        f"偏好{','.join(request.preferences) if request.preferences else '无特殊偏好'}，"
        f"预算等级{request.budget}，实际总花费{result.total_budget.total:.0f}元。"
        f"游览了{'、'.join(unique_attractions[:8])}等景点。"
    )

    if unique_hotels:
        memory_text += f"住在{unique_hotels[0]}。"

    if result.total_budget.is_over_budget:
        memory_text += "本次行程实际花费超出预算。"

    return memory_text
```

示例输出：
> "2026-03-04，用户去北京旅行3天，偏好历史文化，预算等级中等，实际总花费2500元。游览了天安门广场、故宫博物院、景山公园、天坛公园、南锣鼓巷等景点。住在全季酒店(王府井店)。"

#### 3.3.2 存储接口

```python
def save_trip_memory(self, user_id: str, memory_text: str, metadata: Dict[str, Any]):
    """存储行程情景记忆到向量库"""
    self.memory_manager.add_memory(
        content=memory_text,
        memory_type="episodic",
        importance=0.8,
        metadata={
            "user_id": user_id,
            "type": "trip_completed",
            "destination": metadata.get("destination", ""),
            "trip_date": metadata.get("trip_date", ""),
        },
    )
```

#### 3.3.3 检索接口

在请求开始时（`node_load_memory` 节点），一次性检索并写入 State：

```python
def retrieve_trip_memories(self, user_id: str, destination: str, preferences: List[str], limit: int = 3) -> List[str]:
    """检索与当前请求相关的历史行程记忆"""
    query = f"{destination} {' '.join(preferences)}"
    memories = self.memory_manager.retrieve_memories(
        query=query,
        memory_types=["episodic"],
        limit=limit,
        min_importance=0.3,
    )
    return [m.content for m in memories]
```

### 3.4 记忆加载节点：node_load_memory

在 LangGraph 图中新增一个节点 `node_load_memory`，位于 `START` 和 `orchestrator` 之间，负责一次性加载所有长期记忆：

```python
def node_load_memory(state: CoordinatorState) -> dict:
    """
    记忆加载节点：在规划开始前一次性加载长期记忆。

    1. 从 Redis 读取用户偏好画像
    2. 从向量库检索相关情景记忆（最多 3 条）
    3. 合并为 memory_context 文本，写入 State
    """
    user_id = state["user_id"]
    request = state["request"]
    destination = request["destination"]
    preferences = request.get("preferences", [])

    # 1. 加载用户偏好画像
    profile_service = UserProfileService(redis_client)
    user_profile = profile_service.get_profile(user_id)

    # 2. 检索情景记忆
    memory_texts = retrieve_trip_memories(user_id, destination, preferences, limit=3)

    # 3. 构建 memory_context
    context_parts = []

    if user_profile.get("trip_count", 0) > 0:
        top_categories = sorted(
            user_profile["preferred_categories"].items(),
            key=lambda x: x[1], reverse=True
        )[:3]
        top_prefs = "、".join([f"{k}({v}次)" for k, v in top_categories])
        context_parts.append(f"用户历史偏好: {top_prefs}，平均每日预算{user_profile['avg_daily_budget']:.0f}元")

        if destination in user_profile.get("visited_cities", []):
            context_parts.append(f"用户曾去过{destination}，注意推荐新的景点")

    if memory_texts:
        context_parts.append("相关历史行程:")
        for text in memory_texts:
            context_parts.append(f"  - {text[:200]}")

    memory_context = "\n".join(context_parts) if context_parts else ""

    return {
        "memory_context": memory_context,
        "user_profile": user_profile,
    }
```

### 3.5 记忆存储节点：node_save_memory

在 `node_assemble_response` 节点末尾（或新增独立节点），负责将本次规划结果写入长期记忆：

```python
def node_save_memory(state: CoordinatorState) -> dict:
    """
    记忆保存节点：规划完成后保存长期记忆。

    1. 增量更新用户偏好画像（Redis）
    2. 存储本次行程摘要到向量库（Milvus）
    """
    user_id = state["user_id"]
    final_response = state["final_response"]
    request = state["request"]

    if not final_response:
        return {}

    # 1. 增量更新用户偏好画像
    profile_service = UserProfileService(redis_client)
    profile_service.update_profile(user_id, request, final_response)

    # 2. 存储行程摘要到向量库
    trip_summary = generate_trip_summary(request, final_response)
    memory_manager = MemoryManager(user_id, config=MemoryConfig(enable_episodic=True))
    memory_manager.store_episodic_memory(trip_summary)

    logger.info(f"✅ [Memory] 已保存用户 {user_id} 的长期记忆")

    return {}
```

### 3.6 LangGraph 图结构变更

```
变更前:
  START → orchestrator → [Send] → workers → should_continue → orchestrator/synthesizer

变更后:
  START → load_memory → orchestrator → [Send] → workers → should_continue → orchestrator/synthesizer → save_memory → END
```

```python
def build_orchestrator_worker_graph() -> StateGraph:
    graph = StateGraph(CoordinatorState)

    # 新增记忆节点
    graph.add_node("load_memory", node_load_memory)
    graph.add_node("save_memory", node_save_memory)

    # 原有节点
    graph.add_node("orchestrator", orchestrator_node)
    graph.add_node("attraction_search_worker", attraction_search_worker)
    graph.add_node("weather_search_worker", weather_search_worker)
    graph.add_node("daily_planning_worker", daily_planning_worker)
    graph.add_node("synthesizer", synthesizer_node)

    # 边
    graph.add_edge(START, "load_memory")              # 新增
    graph.add_edge("load_memory", "orchestrator")      # 新增

    graph.add_conditional_edges(
        "orchestrator",
        assign_workers,
        ["attraction_search_worker", "weather_search_worker", "daily_planning_worker"]
    )

    for worker in ["attraction_search_worker", "weather_search_worker", "daily_planning_worker"]:
        graph.add_conditional_edges(
            worker,
            should_continue,
            {
                "orchestrator": "orchestrator",
                "synthesizer": "synthesizer"
            }
        )

    graph.add_edge("synthesizer", "save_memory")  # 新增
    graph.add_edge("save_memory", END)           # 新增

    return graph
```

## 四、各层对比

| 维度 | 短期记忆 | 长期-偏好画像 | 长期-情景记忆 |
|------|---------|-------------|-------------|
| **载体** | LangGraph State（内存） | Redis Hash | Milvus / FAISS |
| **数据格式** | TypedDict 结构化 | JSON 结构化 | 自然语言文本 |
| **生命周期** | 单次请求 | 永久（可衰减） | 永久 |
| **查询方式** | 直接访问 State 字段 | Key-Value 精确查询 | 向量语义检索 |
| **查询频次/请求** | 每个节点都访问 | 1 次（load_memory） | 1 次（load_memory） |
| **写入时机** | 每个节点自动更新 | 规划完成后（save_memory） | 规划完成后（save_memory） |
| **典型用途** | 已分配景点去重、每日摘要 | 过滤去过的景点、预算参考 | "上次去北京住哪里" |

## 六、降级策略

| 场景 | 降级方式 |
|------|---------|
| Redis 不可用 | `node_load_memory` 返回空 profile，不影响规划流程 |
| 向量库不可用 | `node_load_memory` 跳过情景记忆检索，memory_context 仅包含偏好画像 |
| Redis + 向量库都不可用 | memory_context 为空字符串，系统退化为无记忆模式（当前行为） |
| `node_save_memory` 失败 | 记录错误日志，不影响已生成的行程结果返回给用户 |
