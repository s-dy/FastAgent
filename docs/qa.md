## Q1: 什么是Agent，有哪些模块？
Agent是一个能够自主理解、决策、执行任务的智能系统。不仅能够调用大语言模型进行对话，更重要的是能够感知环境（理解当前的状态和任务）、规划决策、执行任务、自我反思。

Agent具备以下模块：
- 感知和规划模块
- LLM 模块
- 工具模块
- 记忆模块
- 自我反思和优化模块

## Q2: ReAct 模式是什么？
React模式的核心思想是让LLM在思考和行动之间交替进行，形成一个思考-行动-观察的循环。使AI可以像人类一样思考-行动-反思，而不是一次性的给出答案。

## Q3: 工具调用的三层防护机制？
1. 第一层：tool_choice 策略切换

在 ReAct 模式下，LLM 有时会在第一轮就"偷懒"，直接返回答案而不调用工具。这会导致：任务无法完成（如酒店规划需要搜索真实数据） 、LLM 产生幻觉（编造不存在的酒店） 、结果质量下降。

设置tool_choice="any" 强制调用工具。确保首轮必须调用工具获取真实数据，避免 LLM 编造信息，返回幻觉数据。若首轮仍未调用，追加警告消息强制重试。

2. 第二层：工具调用次数阈值 + 停止提醒

LLM 在 ReAct 模式下可能会"过度搜索"，用不同关键词反复搜索同一类信息：如"王府井"、"王府井广场"、"王府井Bridge"。导致浪费 Token 和 API 调用次数、增加响应延迟。

设置阈值tool_call_threshold=2 确保 LLM 在工具调用次数 ≥ 2 时，自动注入引导消息"你已经搜索到了足够的数据，请立即输出最终结果"，通过 Prompt 层面引导 LLM 收敛。

由于酒店规划和餐饮规划通常 1 次搜索就够了，所以阈值设置为 2。

3. 第三层：硬性迭代上限

当LLM 陷入"完美主义"陷阱，总觉得搜索结果不够好，或产生幻觉，认为需要搜索更多信息。这会导致 Token 消耗暴增、请求超时。

设置 max_iterations=8 作为最终兜底，达到上限后强制取最后一条 AI 消息返回。

## Q4: 你实现了长短期记忆架构（短期 State + 长期偏好 Redis），每一层解决什么问题？

1. 短期 State：保存当前任务状态，存储当前行程规划的临时数据，解决节点间的数据传递和状态共享问题。
2. 长期偏好 Redis：保存用户偏好，存储用户偏好数据以及历史行程，解决用户个性化推荐和偏好学习问题。

## Q5: 你使用的是通义千问 qwen-plus 模型，能介绍一下这个模型的特点吗？它和 GPT-4、Claude 相比有什么优劣？

中文用户为主：系统面向中文用户，需要理解中文的旅游偏好、文化背景
成本敏感：旅行规划需要多次 LLM 调用（景点搜索、酒店推荐、餐饮规划等），成本控制很重要
中文地名识别：对中文地名、景点名称的理解更准确
国内服务集成：与高德地图等国内服务的集成更顺畅

## Q6: 什么是 Token？
Token 是 LLM 处理文本的基本单位。不同于人类理解的"单词"或"字符"，Token 是模型内部使用的最小语义单元。

- 英文 Token 计算方式
英文使用 BPE（Byte Pair Encoding） 分词算法：

常见单词通常是一个 Token（如 "hello"、"world"）
罕见词会被拆分成多个 Token（如 "unbelievable" → "un", "believ", "able"）
标点符号和空格也占用 Token
- 中文 Token 计算方式
中文使用更复杂的分词策略：

常用词：可能是一个 Token（如"北京"、"故宫"）
单字：通常是 1-2 个 Token（如"我"、"你"）
生僻字：可能占用更多 Token
