# 问题：预算控制形同虚设，用户预算偏好未真正约束 Agent 输出

## 问题描述

用户在规划请求中可以指定预算水平（经济/中等/豪华），但这个预算偏好在实际的 Agent 规划流程中并没有形成有效的约束。系统的预算计算是"事后统计"而非"事前控制"，导致用户选择"经济"预算时，LLM 可能推荐五星级酒店和高档餐厅。

## 问题现象

1. 用户选择"经济"预算，但推荐的酒店价格为 800 元/晚
2. 用户选择"豪华"预算，但推荐的餐厅人均只有 30 元
3. 总预算金额与用户期望的预算水平严重不匹配

## 代码层面的根因

### 1. 交通费用完全硬编码

```python
# planner.py 第 64-69 行
TRANSPORT_COST_PER_DAY = {
    "经济": 30.0,
    "中等": 60.0,
    "适中": 60.0,
    "豪华": 150.0,
}
```

交通费用与实际景点间距离、交通方式完全无关，只是按预算等级硬编码一个固定值。

### 2. 预算计算是"事后统计"而非"事前控制"

`_calculate_daily_budget()` 方法（第 359-410 行）只是将 Agent 输出的各项费用做简单加法，没有任何预算约束逻辑：

```python
def _calculate_daily_budget(self, attractions_data, hotel_data, dining_data, budget_level):
    # 只是简单累加各项费用
    attraction_ticket_cost = sum(a.get("ticket_price", 0) for a in attractions_data)
    hotel_cost = hotel_data.get("estimated_cost", 0)
    dining_cost = sum(m.get("estimated_cost", 0) for m in dining_data)
    transport_cost = TRANSPORT_COST_PER_DAY.get(budget_level, 60.0)  # 硬编码
    # 没有检查总费用是否超出预算范围
```

### 3. Agent Prompt 中预算约束过于模糊

酒店和餐饮 Agent 的 Prompt 中只传入了 `budget_level` 字符串（如"中等"），但没有给出具体的价格范围约束：

```python
# _build_daily_hotel_prompt 中
f"**预算水平：** {budget_level}\n"
# 没有说明"中等"对应的具体价格范围是多少
```

LLM 对"经济"、"中等"、"豪华"的理解因模型和上下文而异，缺乏确定性。

### 4. 没有预算超标检测和调整机制

Phase3 中计算完总预算后，即使总费用远超用户预期，系统也不会触发任何调整。

## 解决方案

### 方案一：在 Prompt 中注入具体的价格范围

定义每个预算等级对应的具体价格区间，注入到 Agent 的 Prompt 中：

```python
BUDGET_RANGES = {
    "经济": {"hotel": "100-300元/晚", "dining_per_meal": "20-50元/人", "daily_total": "200-500元/天"},
    "中等": {"hotel": "300-600元/晚", "dining_per_meal": "50-100元/人", "daily_total": "500-1000元/天"},
    "豪华": {"hotel": "600-1500元/晚", "dining_per_meal": "100-300元/人", "daily_total": "1000-2500元/天"},
}
```

在构建 Prompt 时附加具体的价格约束：

```
**预算水平：** 中等
**酒店价格范围：** 300-600元/晚
**餐饮人均范围：** 50-100元/人
请确保推荐的酒店和餐饮价格在上述范围内。
```

### 方案二：增加预算超标检测和重新规划

在 `_calculate_daily_budget()` 之后增加预算校验逻辑：

```python
def _check_budget_compliance(self, daily_budget, budget_level):
    max_daily = {"经济": 500, "中等": 1000, "豪华": 2500}
    if daily_budget.total > max_daily.get(budget_level, 1000) * 1.5:
        return False  # 超标 50% 以上，需要重新规划
    return True
```

### 方案三：交通费用基于实际距离估算

利用 Phase2 中已有的景点位置数据，基于 Haversine 距离估算交通费用：

```python
def _estimate_transport_cost(self, attractions, budget_level):
    total_distance = 0
    for i in range(len(attractions) - 1):
        total_distance += self._calculate_distance(...)
    
    cost_per_km = {"经济": 1.5, "中等": 3.0, "豪华": 6.0}  # 公交/打车/专车

```
