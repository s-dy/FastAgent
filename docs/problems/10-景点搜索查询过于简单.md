# 问题：景点搜索查询只使用第一个偏好关键词，搜索结果覆盖面不足

## 问题描述

Phase1 的景点搜索查询构建逻辑过于简单，只使用了用户偏好列表中的第一个关键词，导致搜索结果的覆盖面严重不足。当用户输入多个偏好（如"历史文化、自然风光、美食"）时，只有"历史文化"相关的景点被搜索到。

## 代码层面的根因

`planner.py` 第 148-151 行：

```python
def _build_attraction_query(self, request: TripPlanRequest) -> str:
    keywords = request.preferences[0] if request.preferences else "景点"
    return f"请使用amap_maps_text_search工具搜索{request.destination}的{keywords}相关景点。"
```

**问题分析：**
- `request.preferences[0]`：只取了偏好列表的第一个元素，其余偏好被完全忽略
- 如果用户输入了 `["历史文化", "自然风光", "美食"]`，只会搜索"历史文化"相关景点
- 搜索查询只调用了一次工具，搜索结果数量有限（高德 API 单次返回约 20 条）

## 影响范围

- Phase2 的景点规划 Agent 只能从有限的候选景点中挑选，导致行程单调
- 用户的多元化偏好无法被满足
- 多天行程中后几天可能出现"无景点可选"的情况

## 解决方案

### 方案一：多关键词合并搜索

将所有偏好关键词合并到一次搜索查询中：

```python
def _build_attraction_query(self, request: TripPlanRequest) -> str:
    if request.preferences:
        keywords = "、".join(request.preferences)
    else:
        keywords = "热门景点"
    return (
        f"请使用工具搜索{request.destination}的景点。"
        f"用户感兴趣的类型包括：{keywords}。"
        f"请尽量搜索覆盖以上所有类型的景点，每种类型至少搜索一次。"
    )
```

### 方案二：多次搜索 + 结果合并

为每个偏好关键词分别发起搜索，然后合并去重：

```python
def _build_attraction_queries(self, request: TripPlanRequest) -> List[str]:
    queries = []
    for preference in (request.preferences or ["热门景点"]):
        queries.append(
            f"请使用工具搜索{request.destination}的{preference}相关景点。"
        )
    return queries
```

在 Phase1 中并行执行多个搜索查询，合并结果后传入 Phase2。

### 方案三：引导 Agent 自主多轮搜索

修改 `ATTRACTION_SEARCH_PROMPT`，引导 Agent 根据用户偏好自主决定搜索策略：

```
你的任务是根据城市和用户偏好搜索合适的景点。

**搜索策略：**
1. 用户可能有多个偏好，你应该为每个偏好类型分别搜索
2. 每次搜索使用不同的关键词，确保覆盖用户的所有偏好
3. 搜索结果应包含至少 15-20 个不同的景点，覆盖多种类型
4. 搜索完成后，合并所有结果并去重，然后总结信息
```

这种方案利用了 ReAct Agent 的多轮工具调用能力，但需要配合工具调用阈值控制（避免搜索过多次）。
