# 问题：前后端数据模型字段差异导致前端崩溃

## 问题描述

后端使用 Pydantic v2 定义数据模型，前端使用 TypeScript 定义类型接口。由于前后端独立开发，两侧的字段命名、数据结构存在大量差异，导致前端页面在渲染行程数据时频繁崩溃。

## 问题现象

前端 `Result.vue` 页面报错：
```
TypeError: Cannot read properties of undefined (reading 'forEach')
```

根本原因是后端返回的字段名与前端期望的字段名不一致，前端直接访问 `undefined` 属性。

## 具体的字段差异清单

| 数据类型 | 后端字段 | 前端期望 | 差异类型 |
|----------|----------|----------|----------|
| 每日行程 | `dining` (List[Meal]) | `dinings` | 字段名不同 |
| 每日行程 | `hotels` (List[Hotel]) | `hotel` (单个对象) | 字段名 + 数据结构不同 |
| 坐标 | `{"longitude": 116.4, "latitude": 39.9}` | `"116.4,39.9"` 或 `[116.4, 39.9]` | 数据格式不同 |
| 景点 | `visit_duration` (int, 分钟) | `visitDuration` | 命名风格不同 (snake_case vs camelCase) |
| 景点 | `ticket_price` (int) | `ticketPrice` | 命名风格不同 |
| 景点 | `image_url` | `imageUrl` | 命名风格不同 |
| 餐饮 | `estimated_cost` (int) | `estimatedCost` | 命名风格不同 |
| 酒店 | `price_range` | `priceRange` | 命名风格不同 |
| 酒店 | `estimated_cost` | `estimatedCost` | 命名风格不同 |
| 预算 | `attraction_ticket_cost` | `attractionTicketCost` | 命名风格不同 |
| 天气 | `day_weather` | `dayWeather` | 命名风格不同 |

## 影响范围

- `Result.vue`：行程详情展示页，直接崩溃
- `EditPlan.vue`：行程编辑页，部分功能异常
- `MapView.vue`：地图组件，坐标解析失败导致标记点不显示
- `BudgetSummary.vue`：预算组件，费用数据为 undefined

## 解决方案

### 创建统一的数据适配层

在 `frontend/src/utils/tripDataAdapter.ts` 中创建了一套完整的适配函数，作为前后端数据的"翻译层"：

```typescript
// 坐标格式统一
function normalizeLocation(location: any): { longitude: number; latitude: number } | null {
    if (!location) return null;
    
    // 处理对象格式 {"longitude": 116.4, "latitude": 39.9}
    if (typeof location === 'object' && 'longitude' in location) {
        return { longitude: Number(location.longitude), latitude: Number(location.latitude) };
    }
    
    // 处理字符串格式 "116.4,39.9"
    if (typeof location === 'string') {
        const parts = location.split(',');
        if (parts.length === 2) {
            return { longitude: Number(parts[0]), latitude: Number(parts[1]) };
        }
    }
    
    // 处理数组格式 [116.4, 39.9]
    if (Array.isArray(location) && location.length === 2) {
        return { longitude: Number(location[0]), latitude: Number(location[1]) };
    }
    
    return null;
}

// 景点数据适配
function normalizeAttraction(raw: any): Attraction {
    return {
        name: raw.name || '',
        address: raw.address || '',
        location: normalizeLocation(raw.location),
        visitDuration: raw.visit_duration || raw.visitDuration || 120,
        description: raw.description || '',
        category: raw.category || '景点',
        rating: raw.rating ? Number(raw.rating) : null,
        imageUrl: raw.image_url || raw.imageUrl || null,
        ticketPrice: raw.ticket_price ?? raw.ticketPrice ?? 0,
    };
}

// 入口函数：适配整个行程数据
export function sanitizeTripPlan(rawPlan: any): TripPlanResponse {
    return {
        ...rawPlan,
        days: (rawPlan.days || []).map((day: any) => ({
            ...day,
            attractions: (day.attractions || []).map(normalizeAttraction),
            dinings: (day.dining || day.dinings || []).map(normalizeDining),
            hotel: normalizeHotel(
                Array.isArray(day.hotels) ? day.hotels[0] : day.hotel
            ),
            weather: day.weather ? normalizeWeather(day.weather) : null,
        })),
    };
}
```

### 在页面组件中统一调用

```typescript
// Result.vue
import { sanitizeTripPlan } from '@/utils/tripDataAdapter';

onMounted(() => {
    const rawData = tripStore.currentTrip;
    const adaptedData = sanitizeTripPlan(rawData);
    // 使用 adaptedData 渲染页面
});
```

## 效果

- 前端页面不再因字段差异而崩溃
- 新增字段差异时只需在适配层添加映射，无需修改多个页面组件
- 适配函数对每个字段都有默认值兜底，即使后端返回 `null` 或 `undefined` 也不会报错
