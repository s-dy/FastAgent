# 后端项目文档

## 概述

智能旅行助手后端基于 **FastAPI** 构建，采用多智能体协作架构，通过 6 个专业 AI Agent 协作完成行程规划。后端提供 RESTful API，支持用户认证、行程规划、行程管理等功能，并集成了限流、熔断、降级、结构化日志等生产级能力。

---

## 技术栈

| 组件 | 技术 | 说明 |
|------|------|------|
| **Web 框架** | FastAPI | 高性能异步 Web 框架 |
| **ASGI 服务器** | Uvicorn | 生产级 ASGI 服务器 |
| **LLM 框架** | fastagent | Agent 编排、工具调用、记忆管理 |
| **LLM 模型** | 通义千问 (qwen-plus) | 通过 DashScope API 调用 |
| **数据验证** | Pydantic v2 | 请求/响应模型校验 |
| **配置管理** | pydantic-settings | 环境变量自动加载 |
| **用户存储** | Redis | 用户数据、行程数据持久化 |
| **向量数据库** | Milvus | 用户记忆向量存储与检索 |
| **密码加密** | bcrypt | 密码哈希加密 |
| **认证** | JWT (PyJWT) | 令牌认证 + 游客模式 |
| **外部工具** | 高德地图 MCP | 景点搜索、酒店搜索、天气查询 |
| **并发执行** | ThreadPoolExecutor | Phase1 并行搜索、Phase2 天内并行 |
| **日志系统** | logging + RotatingFileHandler | 结构化 JSON 日志 + 轮转 |

## 启动方式

### 环境要求

- **Python** >= 3.11
- **Redis** 服务运行中
- **Milvus** 向量数据库运行中（用于记忆检索）

### 安装依赖

```bash
# 使用 uv（推荐）
uv sync

# 或使用 pip
pip install pydantic pydantic-settings fastapi uvicorn redis bcrypt PyJWT python-dotenv
```

### 配置环境变量

在项目根目录创建 `.env` 文件：

```env
# LLM 配置（必填）
DASHSCOPE_API_KEY=your_api_key
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_MODEL_NAME=qwen-plus-2025-12-01

# 高德地图 MCP（必填）
AMAP_MCP_KEY=your_amap_key

# LangSmith 追踪（可选）
LANGSMITH_API_KEY=your_langsmith_key

# Langfuse 可观测性（可选）
LANGFUSE_SECRET_KEY=your_secret_key
LANGFUSE_PUBLIC_KEY=your_public_key
LANGFUSE_BASE_URL=https://cloud.langfuse.com
```

### 启动服务

```bash
python run.py
```

服务默认监听 `0.0.0.0:8000`，启动后可访问：
- **API 文档**：`http://localhost:8000/docs`（Swagger UI）

## 认证机制

系统支持两种认证模式，通过 `AuthMiddleware` 统一处理：

### JWT 令牌认证（注册用户）

1. 用户通过 `/api/v1/auth/login` 或 `/api/v1/auth/register` 获取 JWT 令牌
2. 后续请求在 `Authorization` 头中携带 `Bearer <token>`
3. 令牌有效期默认 24 小时，包含 `user_id`、`username`、签发时间、过期时间
4. 使用 HS256 算法签名

### 游客模式（未注册用户）

1. 无需登录，系统自动分配 `guest_id`（UUID）
2. 通过 Cookie 持久化，有效期 30 天
3. 游客的 `user_id` 格式为 `guest_{uuid}`
4. 游客同样可以使用行程规划功能

### 认证流程

```
请求到达
  │
  ├── 有 Authorization: Bearer <token>？
  │     ├── 是 → JWT 验证 → 成功 → 注册用户身份
  │     └── 否 ↓
  │
  ├── 有 Cookie: guest_id？
  │     ├── 是 → 查找会话 → 成功 → 游客身份
  │     └── 否 ↓
  │
  └── 创建新游客会话 → 设置 Cookie → 游客身份
```

### 跳过认证的端点

- `GET /health`
- `POST /auth/login`
- `POST /auth/register`

## 中间件链

中间件按注册顺序从外到内执行（FastAPI/Starlette 的中间件执行顺序是后注册的先执行）：

```
请求 → RequestIDMiddleware → AuthMiddleware → RateLimitMiddleware → CORS → 路由处理
响应 ← RequestIDMiddleware ← AuthMiddleware ← RateLimitMiddleware ← CORS ← 路由处理
```

### 1. RequestIDMiddleware（请求 ID）

- 为每个请求生成唯一 UUID
- 通过 `contextvars` 存储，全链路可追踪
- 响应头中添加 `X-Request-ID`

### 2. AuthMiddleware（认证）

- JWT 令牌验证 + 游客 Cookie 管理
- 将用户信息注入 `request.state.user`
- 详见上方「认证机制」章节

### 3. RateLimitMiddleware（限流）

- **算法**：滑动窗口（1 秒窗口）
- **全局限流**：100 请求/秒
- **IP 限流**：20 请求/秒
- 超限返回 `429 Too Many Requests`
- 健康检查端点 `/health` 不受限流

### 4. CORSMiddleware（跨域）

- 允许的源：`http://localhost:5173`、`http://localhost:3000`（可通过 `CORS_ORIGINS` 配置）
- 允许所有 HTTP 方法和请求头
- 允许携带凭证（Cookie）

## 熔断与降级

### 熔断器 (`CircuitBreaker`)

基于失败计数的简化熔断器实现：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `failure_threshold` | 5 | 连续失败次数阈值 |
| `timeout` | 60s | 熔断后自动恢复等待时间 |

**状态流转**：

```
Closed（正常）──失败次数 >= 阈值──→ Open（熔断，快速失败）
                                      │
                                  超过 timeout
                                      │
                                      ▼
                                  Closed（恢复）
```

- 通过 `CircuitBreakerManager` 全局管理多个熔断器实例
- 成功调用后自动重置失败计数

### 降级策略

提供两个装饰器：

- **`@fallback_response(default_value)`**：函数调用失败时返回默认值
- **`@circuit_breaker_with_fallback(...)`**：结合熔断器，熔断或失败时返回降级值

## 异常处理

### 错误码体系

错误码按模块分段：

| 范围 | 模块 | 示例 |
|------|------|------|
| `0` | 成功 | `SUCCESS` |
| `1000-1999` | 通用错误 | `INVALID_REQUEST`、`MISSING_PARAMETER`、`INVALID_PARAMETER` |
| `2000-2999` | 业务错误 | `TRIP_PLAN_FAILED`、`UNSUPPORTED_CITY`、`INVALID_DATE_RANGE` |
| `3000-3999` | 服务错误 | `LLM_SERVICE_ERROR`、`LLM_TIMEOUT`、`MAP_SERVICE_ERROR` |
| `4000-4999` | 系统错误 | `DATABASE_ERROR`、`CIRCUIT_BREAKER_OPEN`、`RATE_LIMIT_EXCEEDED` |
| `5000-5999` | 认证错误 | `UNAUTHORIZED`、`FORBIDDEN`、`TOKEN_EXPIRED` |

### 异常类层次结构

```
Exception
└── BaseAppException          # 应用基础异常（含 error_code + message + details）
    ├── BusinessException     # 业务异常（参数错误、规划失败等）
    ├── ValidationException   # 参数验证异常
    └── ServiceException      # 服务异常
        └── ExternalServiceException  # 外部服务异常
            ├── LLMServiceException   # LLM 服务异常
            ├── MapServiceException   # 地图服务异常
            └── ImageServiceException # 图片服务异常
```

### 统一错误响应格式

所有异常通过 `global_exception_handler` 统一处理，返回标准 JSON：

```json
{
  "success": false,
  "error_code": 2000,
  "error_message": "行程规划失败",
  "details": { "error_type": "TimeoutError" },
  "request_id": "uuid"
}
```

处理优先级：`BaseAppException` → `RequestValidationError` → `HTTPException` → 未知异常

## 数据存储

### Redis 存储结构

| Key 模式 | 类型 | 说明 | 过期时间 |
|----------|------|------|---------|
| `user:{username}` | Hash | 用户数据（user_id、password、phone、gender 等） | 永不过期 |
| `user_index:{user_id}` | String | 用户 ID → 用户名的反向索引 | 永不过期 |
| `trip:{trip_id}` | String (JSON) | 完整行程数据 | 1 年 |
| `user_trips:{user_id}` | Sorted Set | 用户的行程 ID 列表（按创建时间排序） | 永不过期 |

### 用户数据字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `user_id` | string | 用户唯一 ID（UUID） |
| `username` | string | 用户名（唯一） |
| `password` | string | bcrypt 加密后的密码哈希 |
| `phone` | string | 手机号 |
| `gender` | string | 性别（male/female/other） |
| `birthday` | string | 生日 |
| `bio` | string | 个人简介 |
| `travel_preferences` | JSON string | 旅行偏好列表 |
| `avatar_url` | string | 头像 URL |

### 密码安全

- 使用 **bcrypt** 算法加密，12 轮 salt
- 超过 72 字节的长密码先经 SHA256 预处理
- 验证时使用 `bcrypt.checkpw` 安全比对

### Milvus 向量存储

- 用于存储用户的旅行记忆（偏好、历史行程摘要）
- 通过 `MemoryManager` 管理，支持 working memory 和 episodic memory
- 配置项：`MILVUS_HOST`（默认 localhost）、`MILVUS_PORT`（默认 19530）、`MILVUS_COLLECTION_NAME`（默认 travel_agent）

## 智能体架构

### 协调器-工作器架构

系统采用**协调器-工作器（Orchestrator-Worker）架构**，基于 LangGraph 的 Send API 实现动态任务调度：

| 阶段 | 说明 | 执行方式 |
|------|------|---------|
| **阶段1** | 并行搜索景点和天气原始数据 | Send API 创建 2 个 Worker 并行执行 |
| **阶段2** | 每日规划（景点、酒店、餐饮） | Send API 创建 N 个 Worker 并行执行（N=天数） |
| **阶段3** | 拼装验证 | Synthesizer 顺序执行 |

### 核心组件

| 组件 | 职责 | 工具调用 |
|-------|------|---------:|
| **Orchestrator** | 任务协调器，分解任务、生成 TripSection、管理任务依赖关系 | ❌ |
| **AttractionSearchWorker** | 景点搜索工作节点，搜索景点 POI | ✅（高德 MCP） |
| **WeatherSearchWorker** | 天气查询工作节点，查询天气预报 | ✅（高德 MCP） |
| **DailyPlanningWorker** | 每日规划工作节点，规划单日行程（景点、酒店、餐饮） | ✅（高德 MCP） |
| **Synthesizer** | 结果合成器，汇总结果、生成标题主题、计算总预算、验证相邻天行程 | ❌ |

### 核心特性

- **Send API 动态节点创建**：运行时动态创建工作节点实例
- **状态共享与聚合**：通过 `operator.add` reducer 自动合并工作节点结果
- **并行执行**：所有工作节点并行运行，大幅提升效率
- **任务依赖管理**：通过条件边自动管理任务间的依赖关系

详细设计文档见：[`多智能体设计.md`](./多智能体设计.md)

### 防无限循环机制

`EnhancedAgent` 基类内置两层防护：

1. **引导总结**：工具调用次数达到 `max_step - 2` 后，追加 user 消息引导 LLM 总结结果
2. **强制禁止**：最后一次迭代时设置 `tool_choice="none"`，从 API 层面禁止工具调用

### 地理位置验证

系统内置 **30 个热门旅游城市**的经纬度范围（`CITY_BOUNDS`），自动校验：

- 景点/酒店/餐厅是否在目标城市范围内（移除异常数据）
- 同一天景点间距离是否超过 50 公里（日志告警）
- 相邻天景点间距离是否超过 100 公里（日志告警）
- 距离计算使用 Haversine 公式

支持的城市包括：北京、上海、广州、深圳、成都、杭州、重庆、武汉、西安、苏州、天津、南京、长沙、郑州、厦门、青岛、大连、三亚、丽江、桂林、昆明、哈尔滨、沈阳、济南、黄山、张家界、敦煌、拉萨、乌鲁木齐、宁波。

### 预算计算

预算由程序化计算，不依赖 LLM：

- **门票费用**：累加每个景点的 `ticket_price`
- **酒店费用**：取酒店的 `estimated_cost`
- **餐饮费用**：累加每顿餐饮的 `estimated_cost`
- **交通费用**：按预算等级取固定值（经济 30 元/天、中等 60 元/天、豪华 150 元/天）

## 上下文管理器

`ContextManager` 提供 Agent 间的数据共享能力，按请求 ID 隔离：

| 方法 | 说明 |
|------|------|
| `share_data(key, data, from_agent)` | Agent 共享数据给其他 Agent |
| `get_shared_data(key)` | 获取其他 Agent 共享的数据 |
| `update_context(agent_name, data, type)` | 更新 Agent 上下文（输入/输出/状态） |
| `get_agent_context(agent_name)` | 获取指定 Agent 的上下文历史 |
| `add_memory_context(type, data)` | 注入用户记忆到上下文 |
| `create_snapshot()` / `restore_from_snapshot()` | 上下文快照与回溯 |

全局管理函数：
- `get_context_manager(request_id)` — 获取或创建上下文管理器
- `remove_context_manager(request_id)` — 请求完成后清理
